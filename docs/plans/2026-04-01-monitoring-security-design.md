## Features

### 2A. Data Drift Detection

A monitoring module that compares incoming prediction request features against
the training data distribution and flags distribution shift.

**New file:** `demandops/monitoring/drift_detector.py`

#### Reference Distributions

Computed during training from the training split only (not val/test), saved to
`artifacts/reference_distributions.json`. Contents per feature in
`FEATURE_COLUMNS`:

- **Decile boundaries** (10 bins from training quantiles) — used for PSI binning
- **Stratified subsample** of 5,000 training values — used for KS two-sample
  test. Subsample size recorded in artifact metadata for reproducibility
- **8×8 correlation matrix** across the 8 continuous features (`zone_id`
  excluded — it is categorical, Pearson correlation against continuous features
  is meaningless). See DECISIONS.md

Generated by a new function in the training pipeline, called from
`scripts/train.py`.

#### Detection Methods

1. **Population Stability Index (PSI)** — bin incoming feature values into the
   same decile boundaries as training data, compute PSI per feature.
   - Thresholds: PSI > 0.1 = warning, PSI > 0.25 = alert
   - Decile-based binning (not equal-width) because features like `zone_id` and
     `hour_of_day` have non-uniform distributions

2. **Kolmogorov-Smirnov test** — `scipy.stats.ks_2samp` per feature, comparing
   accumulated samples against the 5,000-point training subsample.
   - Reports: KS statistic + p-value per feature
   - Flags drift when p-value < 0.05

3. **Correlation shift** — Frobenius norm of (current correlation matrix −
   training correlation matrix), normalized by number of feature pairs.
   - Computed on the 8 continuous features only (`zone_id` excluded)
   - Catches joint distribution shifts invisible to per-feature tests
   - Threshold TBD empirically, likely ~0.1 for warning

#### Accumulator

`DriftAccumulator` class wrapping `collections.deque(maxlen=1000)`.
Thread-safe via `threading.Lock`. Appends feature vectors from every prediction
request (single and batch).

- **Minimum sample threshold:** configurable, default 100. Below threshold,
  `GET /monitoring/drift` returns
  `{"status": "insufficient_samples", "collected": N, "required": 100}`
- **On-demand computation:** drift metrics are computed only when
  `/monitoring/drift` is called — no background threads, no periodic timers
- **Restart behavior:** accumulator resets to empty on server restart. The
  bounded deque accumulates samples passively; drift is a point-in-time
  computation against the training reference

#### Endpoint

`GET /monitoring/drift` — returns current drift status per feature (PSI, KS
stat, KS p-value, drift verdict) plus aggregate correlation shift score.

### 2B. Prediction Quality Monitoring

Track prediction accuracy over time when ground truth becomes available.
Standard in demand forecasting where actuals arrive with a lag.

**New file:** `demandops/monitoring/quality_tracker.py`

#### Prediction Logging

Every authenticated prediction (single and batch) writes a row to SQLite
(`data/demandops.db`, table `prediction_log`):

```
prediction_id  TEXT PRIMARY KEY  -- UUID, returned in PredictResponse
zone_id        INTEGER
hour_ts        TEXT
predicted_value REAL
actual_value   REAL NULL         -- filled when actuals arrive
created_at     TEXT
```

Indexed on `(prediction_id)` and `(zone_id, hour_ts)`.

- `prediction_id` is a new field on `PredictResponse`
- Synchronous write (~1ms per request, negligible for demo)

#### Actuals Submission

`POST /monitoring/actuals` (auth-gated) accepts a list of:
- `{prediction_id, actual_value}` — direct match
- `{zone_id, hour_ts, actual_value}` — matches most recent prediction for that
  zone/timestamp pair (documented: when multiple predictions exist for the same
  key, the most recent is matched)

Returns:
- `matched_count`, `unmatched_count`
- `warnings` list for unmatched actuals (not a 4xx — partial matches are
  expected when actuals arrive for predictions made before the last restart)

#### Quality Computation

`GET /monitoring/quality?window=7d` queries matched prediction/actual pairs
within the window:

- **Metrics:** rolling MAE, RMSE, sMAPE
- **sMAPE instead of MAPE:** demand data contains genuine zeros; MAPE divides
  by actual values, so a single zero actual produces infinite MAPE. sMAPE is
  bounded. Zero-actual exclusion count reported alongside. See DECISIONS.md
- **Insufficient pairs gate:** fewer than 10 matched pairs →
  `{"status": "insufficient_matched_pairs", "matched": N, "required": 10}`

#### Drift-Quality Correlation

Computed at the route layer, not inside the module. When MAE exceeds the
regression gate threshold × configurable margin (default 1.2×), the response
includes a `drift_correlation` field reporting current drift status alongside
quality degradation. No cross-module import — the route handler queries both
the quality tracker and drift detector, stitches the result.

### 2C. API Authentication & Rate Limiting

API key auth with per-key rate limiting on write/compute endpoints.

**New file:** `demandops/security/auth.py`

#### Key Storage

SQLite table `api_keys` in `data/demandops.db`:

```
key_hash        TEXT PRIMARY KEY  -- SHA-256 of raw key
client_name     TEXT
created_at      TEXT
rate_limit      INTEGER           -- requests per minute
max_batch_size  INTEGER DEFAULT 10000
is_active       BOOLEAN
```

Keys are SHA-256 hashed at rest. Raw key shown exactly once at creation time.

#### Key Management CLI

`python -m demandops.manage_keys <command>`

- `create --client "analytics_team" --rate-limit 100` — generates
  `secrets.token_urlsafe(32)`, hashes, inserts, prints raw key once
- `list` — shows client_name, created_at, rate_limit, is_active (never hashes)
- `revoke --client "analytics_team"` — sets `is_active=0`

#### Auth Dependency

FastAPI `Depends` callable `requires_auth`:

- Extracts `Authorization: Bearer <key>` from header
- SHA-256 hashes the key, looks up in SQLite, checks `is_active`
- Returns `client_name` for downstream use (logging, rate limit lookup)
- Returns 401 with `{"detail": "Invalid or inactive API key"}` on failure —
  intentionally vague to prevent oracle attacks distinguishing "key doesn't
  exist" from "key revoked"
- Applied per-route via `Depends`, not as global middleware

#### Auth Boundary

| Endpoint | Auth |
|---|---|
| `POST /predict` | Yes |
| `POST /predict/batch` | Yes |
| `POST /monitoring/actuals` | Yes |
| `GET /monitoring/drift` | No |
| `GET /monitoring/quality` | No |
| `GET /health` | No |
| `GET /metrics` | No |

Rule: auth on anything that writes or costs compute. Monitoring reads and
health checks are operational plumbing.

#### Rate Limiting

In-memory `dict[str, list[float]]` mapping `client_name` to request timestamps
(sliding window, last 60 seconds). Checked after auth succeeds. Returns 429
with `Retry-After` header when exceeded. Resets on restart — acceptable for
demo scale.

#### Batch Hardening

`max_batch_size` per key (default 10,000). Returns 413 if exceeded.

## DECISIONS.md Additions

1. **Why PSI + KS + correlation matrix (not autoencoder):** PSI is industry
   standard but bin-based, insensitive to tail shifts. KS complements
   per-feature with distribution-wide sensitivity. Correlation matrix catches
   joint shifts invisible to per-feature tests. An autoencoder was considered
   but rejected: with 9 features and a bottleneck of 8, the compression ratio
   is too low for meaningful anomaly detection — reconstruction error would be
   dominated by noise, not distributional novelty
2. **Why sMAPE over MAPE:** demand data contains genuine zeros; MAPE produces
   infinite values on zero actuals that poison the aggregate
3. **Why `zone_id` excluded from correlation matrix:** categorical feature
   (261 zones), Pearson correlation against continuous features is meaningless
4. **Why SQLite for prediction logging + auth:** no external infra, portable,
   sufficient for demo scale
5. **Why intentionally vague 401:** prevents oracle attacks distinguishing
   "key doesn't exist" from "key revoked"
6. **Why KS uses 5,000-point subsample:** nonparametric test without bloating
   the reference artifact with full training data
7. **Why on-demand drift computation instead of continuous monitoring:** avoids
   background threads and statefulness in the serving layer. Bounded deque
   accumulates samples passively; drift is computed only when
   `/monitoring/drift` is called. Simpler to test, no concurrency bugs

## Test Plan

### Drift Detection (`tests/test_drift.py`)

- **PSI triggers on shifted data:** synthetic feature array with `hour_of_day`
  shifted to narrow range vs uniform training reference. Verify PSI > 0.25 for
  shifted feature, PSI ≈ 0 for unshifted
- **KS triggers on shifted data:** same synthetic shift, verify p-value < 0.05
  for shifted, p-value > 0.05 for unshifted
- **No false alarms:** samples from same distribution as training. Verify
  PSI < 0.1, KS p-value > 0.05, correlation shift below threshold on all
  features
- **Correlation shift detection:** construct samples where individual features
  match training marginals but correlations are altered (flip sign of
  `lag_1h`/`rolling_mean_24h` correlation). Verify Frobenius norm exceeds
  threshold while per-feature PSI/KS stay clean
- **Insufficient samples gate:** accumulate 50, call drift endpoint, verify
  `{"status": "insufficient_samples", "collected": 50, "required": 100}`
- **Deque boundary:** push 1,200 samples, verify accumulator holds exactly
  1,000 (oldest 200 evicted), drift computed on most recent 1,000
- **Concurrent accumulator writes:** 10 threads × 100 samples, verify
  count = 1,000 and no partial feature vectors
- **Reference distribution serialization:** run artifact generation, verify
  JSON contains expected keys, subsample sizes, 8×8 correlation matrix

### Quality Monitoring (`tests/test_quality.py`)

- **End-to-end:** log predictions, submit actuals, query quality. Verify
  MAE/RMSE/sMAPE against hand-calculated values
- **sMAPE with zeros:** submit zero actuals, verify sMAPE bounded (not
  infinite), zero-exclusion count reported
- **Insufficient pairs gate:** < 10 matched pairs → graceful response
- **Ambiguous actuals:** two predictions for same `(zone_id, hour_ts)`,
  submit by zone/timestamp key, verify most-recent matched
- **Window filtering:** predictions across wide time range, query
  `window=1d`, verify only recent pairs
- **Drift-quality correlation:** mock drift detector returning alert state +
  degraded quality, verify `drift_correlation` field present

### Auth (`tests/test_auth.py`)

- **Valid key → 200**, invalid → 401, revoked → 401. Same error message
- **Missing header → 401** (not 500)
- **Rate limiting:** `rate_limit + 1` requests in rapid succession, verify
  429 with `Retry-After`
- **Batch size enforcement:** exceed per-key `max_batch_size`, verify 413
- **Key management CLI:** create (printed once), list (no hashes), revoke
  (inactive)
- **Prediction logging:** authenticated prediction → row in SQLite with
  correct `prediction_id`
- **Concurrent SQLite writes:** parallel authenticated predictions, verify
  no database-locked errors

All tests use isolated SQLite DB (tmp path fixture) and synthetic reference
distributions — no dependency on real training data or artifacts.
